# Design and primary references

## Serial control

[PE43703 datasheet 70-0245-05](https://www.psemi.com/wp-content/uploads/pdf/obs/pe43703ds.pdf), pp. 7–11, tables 5/7/8/10–13 and figure 29, is the serial/voltage authority. It agrees with a 16-bit transaction: Q0–Q6 hold attenuation ×4, Q7/D7 is zero, Q8–Q10 carry address A0–A2, and Q11–Q15 are don't-care address bits set to zero here. Q0 enters first. Address is fixed at zero. Data shifts on rising CLK while LE stays low; LE then goes high and low.

The device allows up to 10 MHz serial clock, with minimum CLK high/low and LE high times of 30 ns and SI setup/hold and last-CLK-to-LE setup of 10 ns. Firmware uses 1 µs delay intervals around transitions, including before/after LE. This is conservative software timing, not measured pad timing. Serial mode requires P/S high, grounded parallel inputs and matching address straps. PE43703 logic high requires at least 2.6 V; logic low at most 1 V. Verify the actual supplies and levels before hardware use.

## STM32 clock, GPIO, reset and UART

[ST DS5319, STM32F103x8/xB datasheet](https://www.st.com/resource/en/datasheet/stm32f103c8.pdf), clock tree, memory and pin tables, establishes the 72 MHz maximum core/APB2 clock, 36 MHz APB1 limit, 64 KiB flash for C8, 20 KiB SRAM, LQFP48 pinout and 2.0–3.6 V MCU supply range. Logic compatibility with the RF chip must be checked at the actual supply and load.

The following official ST source files provide directly inspectable register definitions and behavior, checked alongside the datasheet. The ADC implementation additionally follows [RM0008 Rev21](https://www.st.com/resource/en/reference_manual/cd00171190.pdf), §§11.3.1, 11.3.4, 11.4 and 11.12, checked through the manufacturer-authored distributor copy linked in [input diagnostics](diagnostics.md). No ST source code is copied into the implementation:

Primary definitions were inspected on 2026-11-19. The loader starts at hardware reset using HSI. The app accepts hardware-like entry from that loader: HSI selected, UART reset, no enabled interrupts/DMA/SysTick, GPIOA high configuration restored and VTOR relocated. Arbitrary third-party loader state is unsupported. Startup initializes data/BSS, the dedicated mailbox and VTOR. It waits a maximum 1,000,000 register polls at each HSE-ready, PLL-ready and clock-switch step. Failure parks with interrupts disabled and `state=2` before enabling GPIO drivers or command input. This is a bounded poll count, not a calibrated timeout in milliseconds. There is no ongoing oscillator-failure recovery or watchdog.

FLASH_ACR prefetch and two wait states are written and read back before switching to HSE×9. AHB/APB2 are /1, APB1 /2, ADC /6. SysTick is a 24-bit free-running down-counter at the 72 MHz core clock, without interrupts; delays use masked unsigned subtraction and intervals shorter than one wrap. The 1 ms boot delay is a guard interval, not power-good measurement.

PB11–PB13 output latches are preloaded low with one BSRR write before enabling 2 MHz push-pull outputs. Each transition updates only those pins via BSRR. PA4–PA7 drive the normal SSD1306-compatible screen in v0.2.0; working roles and the two-unit border comparison are recorded in [OLED observations](oled-probe.md#observed-wiring-on-two-units), while exact controller silicon remains unidentified. USART1 uses PA9 AF push-pull and PA10 floating input; BRR=625 (`39 + 1/16`) gives 115200 at PCLK2=72 MHz. Reset CR2/CR3 and configured CR1 give 8N1 without flow control or interrupts. UART transmit uses a bounded 64-byte queue, serviced without waiting for TXE; receive errors discard the current line. A loader handoff waits for the queued reply to drain, then waits boundedly for UART TC. Clients must wait for each reply, since continuous pipelining can overrun this polling interface.

## Input-only ADC diagnostic

`firmware/adc.c` serializes ADC1 ownership between explicit `adc` / `diag adc` UART requests and automatic button samples. The parser delegates exactly that valid line to the synchronous bounded diagnostic; the automatic button sampler uses the same driver ownership between requests in v0.2.0. ADC1 is reset per request, channel 1 is sampled once at APB2/6 with 239.5-cycle acquisition, and cleanup restores PA1 plus the ADC clock/reset state on success or timeout. The driver refuses an already-enabled/reset ADC rather than destroying another owner’s state. The PE43703 controller and mailbox ABI are unchanged. See [diagnostic commands, timing and hardware limits](diagnostics.md).

## OLED probe and UART scheduling

The opt-in `firmware/oled.c` state machine tries 96 fixed role/controller combinations, one byte or control transition per main-loop pass. It never sleeps for a display hold. The main loop extends the existing SysTick down-counter into milliseconds using modular deltas; all active work units are shorter than its 233 ms wrap under the working-clock contract. A 210-second overall deadline applies even when TX output is backpressured. UART indices are announced before each trial, only when queue space is available.

A 64-byte TX queue preserves whole queued lines while allowing RX processing between transmitted bytes. Before consuming an RX byte or announcing a trial, at least 16 free bytes are required for its maximum response. Output is nonblocking; UART TC still gates the final reset request after the queue drains. Valid SET/bootloader commands cancel the OLED task during console dispatch; successful mailbox SET/permutation commands cancel it in the same main-loop pass. OLED callbacks mask BSRR and mode/latch restoration to PA4–PA7. GPIOA's other modes and GPIOB's RF bus are untouched. See [profile, exact mappings, assumptions and timing](oled-probe.md).

## Applied-state display and local control

The v0.2.0 candidate implements the fixed SSD1306-compatible, column-zero screen on PA6/SCK, PA7/MOSI, PA5/D/C and PA4/RES. The two-unit observations support this command compatibility, not an exact silicon identity. The new normal screen, automatic buttons and lease protocol have offline coverage only; they have not been installed or qualified on either unit.

`Controller.qdb` is the single applied attenuation state. `send_frame` publishes it, its source and the issued count only after the PE43703 LE pulse returns low. USB `set`, host profiles/schedules, local OK and mailbox changes all cause a screen refresh from that completed transaction. The large APPLIED value is latched software control state, not independently measured RF attenuation. PENDING is visibly separate and never becomes APPLIED until OK completes the latch. Boot issues zero before any display or command service.

The screen shows the last applied source (BOOT, USB or LOCAL) separately from USB LOCK/UNLOCKED. Acquiring a profile lease does not rewrite the last source. A one-shot `set` updates the source to USB without creating a lock. Buttons edit pending attenuation in bounded quarter-dB units; PLUS/MINUS use the selected 0.25/1/5 dB step, RIGHT cycles forward through the steps and LEFT backward. Values clamp at 0.00 and 31.75 dB; OK applies. There is no autorepeat. See [sampling, bands and debounce](diagnostics.md#button-processing-in-v020).

### USB profile ownership

`profile` is a side-effect-free capability query, returning `profile 1\r\n`. `profile <token>` acquires a 10-second lease only if unlocked; `<token>` is exactly eight lowercase hexadecimal digits and nonzero. The reply is `ok profile\r\n`, or `err busy\r\n` if already locked. `profile keep <token>` renews only that active lease (`ok keep\r\n`); `profile end <token>` releases it (`ok end\r\n`). A mismatched or expired token returns `err lock\r\n`. Malformed commands return the existing `err\r\n`. Tokens prevent stale renew/release messages from affecting a later owner; they are not authentication.

While locked, **local buttons cannot change pending, step or applied attenuation**. The main loop checks expiry and completed USB/mailbox transactions before sampling buttons. Acquisition, release/expiry and each external applied change discard pending edits and require a fresh debounced release before another key can act. Thus a held OK cannot restore an old local edit when remote ownership ends. Existing USB set/get and debug mailbox commands retain their explicit behavior; exclusive host and mailbox ownership remains mandatory.

Updated [attctl](attctl.md#firmware-profile-leases) acquires both leases before the first profile setting, renews during holds and before each unit's setting, attempts both independent zero cleanups, then releases its leases. Capability probing falls back only on the exact `err` response from older firmware, whose buttons are inert. Older host controllers can still set/get v0.2.0, but must adopt the lease protocol to exclude local buttons during a schedule.

There is no USB disconnect signal through the CH340 UART interface. If the host stops renewing (disconnect, crash or SIGKILL), the lease expires after 10 seconds without changing applied attenuation. Pending then resets to applied, and local control resumes only after release debounce. Reset clears leases and applies boot zero. Zero after host failure is not guaranteed; lease expiry is not an RF failsafe. A failed keep never silently reacquires ownership or replays a profile setting.

### Scheduling and diagnostic ownership

Automatic PA1 conversions use a nonblocking register state machine: one phase per loop, 2 µs power stabilization, and a 100 µs deadline for each phase. A new conversion starts no sooner than 5 ms after the preceding start, with no catch-up bursts. ADC and explicit raw diagnostics serialize; the latter cancel an in-progress automatic conversion before using the existing single-shot diagnostic.

Normal rendering sends at most one byte per loop (25 µs explicit delay), or one reset transition (20 µs), with no framebuffer or hold busy wait. A dirty applied-state frame restarts from the top, keeping APPLIED first. The legacy role sweep temporarily owns the OLED and suppresses local actions; completion/cancellation restores normal rendering. `oledtest` temporarily shows a labeled, fixed-column alignment pattern, suppresses buttons and restores the screen after a 10-second visible hold or a 12-second hard deadline. Valid SET cancels either diagnostic and applies normally. Deadline cleanup does not depend on UART output space. See [OLED commands and hardware limits](oled-probe.md).

## Destructive installation semantics

[ST PM0075 Rev 2 §2.4.1](https://www.st.com/resource/en/programming_manual/cd00283419-stm32f10xxx-flash-memory-microcontrollers-stmicroelectronics.pdf) specifies mass erase when changing F1 RDP to unprotected and power-on reset afterward. [OpenOCD's STM32F1 flash commands](https://openocd.org/doc/html/Flash-Commands.html) document `stm32f1x unlock 0` as destructive on a protected unit. The tooling does not attempt protection bypass, readout exploits or recovery of protected stock code.

Plans explicitly support two native ST-Link profiles: `native-swd` uses the newer `interface/stlink.cfg` with `swd`; `native-dapdirect` uses OpenOCD 0.12.0 `interface/stlink-dap.cfg` with `dapdirect_swd`. There is no transport fallback. `tools/swd.py` defers Cortex-M examination before `init`, removes the included examine-end MMIO write hook, selects a memory-only AP0 target, disables server ports, and sets 100 kHz after included configurations. Mailbox/status and pre-identity checks request no core examination or MCU memory writes. Attachment still involves debugger/adapter activity whose opaque physical effects are not excluded by offline tests. Intentional core examination/reset/halt for installation occurs only after the relevant identity checks.

Erase identity is explicitly different from programming identity: a protected target can make UID/system-memory reads unavailable. Erase requires an attended sole-wired-target assertion, exact adapter serial, DPIDR/full IDCODE, and exact recorded OBR/WRPR. It does not require a protected UID. The standard flash driver can attempt a blocked density read during its probe; the bank is explicitly configured as 64 KiB and the narrow known protected-density diagnostic is retained. After actual POR, a separate read-only phase checks inactive protection, preserved options, actual 64 KiB density and a real UID. All programming and mailbox operations then require that UID. No invented UID, silent guard removal or alternate-target scan is supported.

The [OpenOCD STM32F1 driver](https://github.com/openocd-org/openocd/blob/v0.12.0/src/flash/nor/stm32f1x.c) reads options through OBR/WRPR and performs destructive unprotection with `stm32f1x unlock 0`. This standard path completed on the examined unit. Its handler can return success despite erase/write failure, so plans capture diagnostics, reject actual unlock errors, require the success marker, and independently check RDP/OPTERR and preserved loaded options after actual POR. Known protected-density probe errors are permitted only within the marked probe, with configured 64 KiB geometry confirmed. Exit zero alone is insufficient.

The former direct FPEC path stopped after option erase when a raw option-flash read failed under active RDP. It has been removed. Neither an erased option block nor a successful driver return proves unprotection; post-POR OBR is authoritative for the loaded RDP state. No raw option-flash verification is attempted by installation plans. See [PM0075 §2.3.5/2.4.1](https://www.st.com/resource/en/programming_manual/pm0075-stm32f10xxx-flash-memory-microcontrollers-stmicroelectronics.pdf) for erased-RDP and destructive-unprotection semantics. No retry or recovery is automatic.

The execution wrapper preserves stdout/stderr and a completion receipt, requires phase-specific success evidence as well as an error-free exit, and consumes one attempt before opening the adapter. Timeout, missing evidence, error diagnostics and partial completion remain unknown/failed outcomes, never permission to repeat unprotection.
